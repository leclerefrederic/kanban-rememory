## Target organization

```text
README.md / documentation/       Human explanations, decisions and one example set
AGENTS.md / CLAUDE.md            Project startup and local permissions
agents/
  index.md, VERSION             Task router and kit version
  guidelines/                  Shared working rules, lean application, Kanban, Batches
  actions/                     Orchestration, Cards, journal, develop/close/resume, alerts
  setup/                       Core/workflow, skills, Batches, Claude check, Telegram, layout
  roles/                       orchestrator.md, writer.md, developer.md, tester.md
  hosts/claude/agents/          Host adapters: writer.md, developer.md, tester.md
  skills/                      Four unchanged kr-* discovery names
  templates/                   Blank record contracts only
  tools/                       Existing executable paths retained
```

Guidelines own invariant decisions and constraints; actions own ordered execution with inputs and outputs; setup owns installation/configuration and verification. A mixed document is split only when its parts are loaded in different journeys. No generic fourth “reference” layer or tiny file per rule. The human User role moves to `documentation/user-responsibilities.md`; binding agent gates remain explicit in the guidelines.

The shared manifesto remains the authority for six principles. Agent lean rules become a concise, faithful operational view with traceable links; the manifesto is loaded when interpreting/revising principles, rather than automatically reread with its full paraphrase on every task. This loading change needs the same behavioral verification as other compression.

## Compatibility choice

Preserve **11 tiny relays**, each linking to canonical content and containing no normative duplication: old root `work-in-a-project.md`, `lean-specifications.md`, `maintain-rememory.md`, `orchestrate-work.md`; old Writer/Developer role paths; the four old `agents/batches/*.md`; `agents/kanban/software-development-workflow.md`. They serve 14 historical links and custom old entry points. Old role relays have no policy frontmatter. No active router loads these relays; fresh core installations need only canonical files, while upgrades retain needed compatibility.

The root therefore has index/version plus four clearly identified compatibility files, rather than many mixed procedures. Retaining every old path would add unnecessary clutter. Rewriting immutable evidence is excluded. A validator-only alias would leave normal Markdown clicks broken, so is not recommended. Archive-era prose remains searchable by stable ID and Git snapshot.
