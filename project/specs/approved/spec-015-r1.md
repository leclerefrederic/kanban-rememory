# Bring Claude Code's Terminal window forward when the user is needed

## Expected outcome

The user can leave Claude Code working on the Mac and return when a decision is needed. KR starts Claude Code in a minimized Terminal window. When Claude needs the user, KR brings that window forward and Remy sends an alert. The user answers in that Terminal session. When Claude resumes working, KR minimizes the window again.

## Scope

- macOS, KR, Terminal and Claude Code. Use an interactive launch for a task the user has authorized. Scheduled checks retain their existing behavior and permissions.
- Start the session minimized and leave it minimized during autonomous work.
- When Claude explicitly signals that it is waiting for the user, restore its Terminal window and bring it to the foreground in its normal size. Use the configured Telegram channel for the intervention alert. With Telegram disabled or unavailable, still bring the window forward.
- The user answers in the same session. Keep the window visible while Claude is still waiting, including if it asks for clarification. Minimize it once Claude signals that work has resumed.
- A period of silence or long-running command does not count as a request for intervention. The focus change and alert happen once per intervention, even if KR receives the same signal more than once.
- Leave other Terminal windows alone. If the session exits while waiting, show in KR that it ended and that the user can no longer reply there.
- This revision covers explicit requests from the agent. Prompts generated by Claude Code itself, including tool permission dialogs, need separate verification before they are included. Recovery after the session ends and answering from Telegram are outside this scope.

## Acceptance criteria

Use a scratch project, an authorized Claude Code task and a configured Telegram test destination. Have Claude ask whether a sample record should be exported as CSV or JSON.

1. Start the task from KR. Its Terminal window is minimized while Claude works. A deliberately slow command neither brings the window forward nor sends an alert.
2. When Claude asks for the format and waits, KR restores the correct window at normal size and Remy delivers one intervention alert. Repeating the same intervention signal leaves the alert count at one.
3. Give an ambiguous answer and have Claude ask for clarification. The window stays visible while the choice is unresolved. Then answer JSON in the same session. Once Claude resumes, the window minimizes and the completed export contains the expected record in JSON.
4. Repeat with Telegram disabled or with a simulated send failure. The correct Terminal window still comes forward and accepts the answer.
5. With a second unrelated Terminal window open, repeat the intervention and resume cycle. KR changes only the session window. Close that session while it is waiting and verify that KR shows it ended and leaves the other window alone.
6. Run an existing scheduled check. It still runs in the background with its existing permissions and opens no Terminal window.
