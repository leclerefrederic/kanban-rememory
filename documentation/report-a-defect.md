# Report a defect

Tell your agent when delivered behavior differs from what was agreed. The agent records it; you do not create a Card yourself.

## Describe what happened

Share the version or build if you know it, the steps, what you expected and what happened instead. Include the exact error and a screenshot when available. Say whether it blocks the work, affects one path or has an acceptable workaround.

> In the version published yesterday, selecting the repository opens a blank window and the app stops responding. I expected the creation form. Here is a screenshot.

If you cannot identify the build or reproduce the problem, say so. The agent records that uncertainty and helps establish evidence; it must not invent a cause or mark the problem resolved.

## How it is tracked

A defect in a Card still in progress returns that Card to rework. A defect in completed work gets a new Card that refers to the original; completed Cards are not reopened. The defect stays open until its correction is verified and delivered.

## Correction or new idea

A correction restores agreed behavior. A request for different behavior goes through scope approval. If the difference is unclear, the agent asks before implementation. Improvements you suggest alongside a defect stay separate from the authorized correction.
